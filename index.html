Executive Summary
자체 파인튜닝 방식은 법률적·기술적 타당성을 상실하였으며, 독립된 Vector DB를 활용하는 RAG 아키텍처로의 전환이 필수적입니다.
01. As-Is 리스크
  • 데이터 파기 불가 (기술적 한계)
  • 개인정보보호법 정면 위배
02. 비즈니스 임팩트
  • 글로벌 규제(FTC) 적발 리스크 고조
  • 알고리즘 전량 폐기에 따른 천문학적 매몰 비용 유발
03. To-Be 솔루션
  • Vector DB 연동 구축
  • 물리적 삭제(Hard Delete) 완벽 구현
  • 설명요구권 100% 충족

구분 기존 RDBMS LLM 파인튜닝
저장 방식 테이블 구조 및 인덱스(Index) 기반 저장 수백억 개 파라미터에 실수형 확률값으로 은닉 (분산 표상)
삭제 가능성 DELETE 쿼리를 통한 특정 레코드(Row) 영구 파기 가능 원본 데이터 소멸 및 족보 상실로 특정 데이터 타겟팅 파기 불가
⚠️ 리스크 경고: 머신 언러닝(Machine Unlearning)의 구조적 한계
  • 강제 삭제(머신 언러닝) 시도 시, 파라미터 연쇄 붕괴 발생
  • 모델 전체의 추론 능력이 상실되는 '재앙적 망각(Catastrophic Forgetting)' 리스크 직면

  • 계약서 내 '입력 데이터 학습 이용 금지(Opt-out)' 특약 필수 반영
